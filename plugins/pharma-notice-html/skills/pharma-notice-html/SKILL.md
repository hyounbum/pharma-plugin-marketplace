# 제약사 공지 통합 HTML

## 목적

사용자가 업로드한 제약사 공지 이미지를 판독해 회사 보고용 공지 초안을 만들고, 사용자 승인 후 기준 HTML 디자인을 유지한 HTML 원본과 PDF를 생성한다.

이미지와 사용자가 직접 제공한 수정값만 사용한다. 외부 웹 검색이나 일반 지식으로 회사명, 제품명, 성분, 보험코드, 약가, 수수료율, 날짜, 규격 등을 보완하지 않는다.

## 반드시 지켜야 할 전체 순서

1. 이미지 업로드 수집
2. 사용자의 업로드 완료 의사 확인
3. 이미지 분석
4. 전체 수정 확인 목록 제시
5. 사용자 수정·제외 반영
6. 전체 수정 확인 목록 재제시
7. 사용자 승인
8. 승인된 데이터로 HTML 생성
9. 같은 HTML로 PDF 생성
10. 실제 파일 링크 반환

순서를 건너뛰지 않는다.

## 이미지 업로드 중

- 사용자가 이미지를 여러 번 나누어 올릴 수 있다.
- 첫 묶음에는 다음 문구로 안내한다.

`계속 올려주시고 마지막에 업로드 완료라고 보내주세요.`

- 가능하면 `1/3`, `2/3` 같은 묶음 번호를 권장할 수 있으나 필수로 요구하지 않는다.
- 이미지는 업로드 순서대로 1부터 번호를 부여한다.
- 사용자가 `업로드 완료`, `사진 끝`, `전부 올림` 등 완료 의사를 밝히기 전에는 분석을 시작하거나 분석 결과를 확정하지 않는다.
- 완료 전 `분석해줘` 요청이 들어와도 현재 업로드 수만 안내하고 완료 문구를 요청한다.
- `analyze_notice_images`는 완료 의사가 확인된 뒤에만 호출한다.

## 이미지 분석

### 사용 가능한 정보

- 원본 이미지에 보이는 내용
- 사용자가 직접 입력한 수정값
- 사용자가 직접 입력한 수기 보완값

### 사용 금지 정보

- 외부 웹 검색
- 의약품 데이터베이스 자동 조회
- 일반 지식에 따른 회사명·제품명·성분·약가 추정
- 비슷한 제품을 근거로 한 보험코드·함량·날짜 추정
- 이미지에 없는 효능효과나 용법용량 추가

### 이미지 단위 처리

- 업로드 순서대로 `sourceImageIndex`를 유지한다.
- 같은 이미지가 중복 업로드되면 한 번만 분석하고 중복 번호를 표시한다.
- 한 공고를 여러 장으로 촬영한 경우 하나의 공고로 합친다.
- 다른 이미지에서 같은 제품 정보가 이어지면 하나의 항목으로 통합한다.
- 중복 제품 행은 한 번만 등록한다.
- 값이 충돌하면 임의 선택하지 말고 충돌로 표시한다.
- 흐리거나 잘린 이미지가 있어도 판독 가능한 나머지는 계속 처리한다.
- 핵심값이 판독되지 않는 이미지는 이미지 번호와 함께 선명한 재업로드를 요청한다.
- 재업로드 후에도 읽지 못하면 해당 유형의 수기 입력 양식을 제공한다.

## 분류 규칙

문서 주제목은 항상 `제약사 공지`다.

상위 섹션은 공고 이미지의 실제 주제에 맞춰 동적으로 구성한다. 내용이 없는 섹션은 만들지 않는다. 같은 성격의 공고는 하나의 섹션과 표로 통합하고, 서로 다른 업무 목적의 내용을 억지로 한 표에 합치지 않는다.

우선 사용하는 표준 섹션은 다음과 같다.

1. `품절 및 입고`
2. `수수료`
3. `의약품 정보`
4. `품목 등록 안내`
5. `제약사 정책 변경`
6. `기타 공지·조치사항`

이미지에 계약 및 거래조건, 반품·정산 정책, 주문·배송, 제품 회수·판매중단, 서류 제출, 시스템 변경, 교육·행사, 담당자 변경 등 다른 주제가 명확하게 있으면 해당 업무를 가장 잘 설명하는 상위 섹션명을 추가할 수 있다. 새 섹션명과 컬럼은 이미지에 보이는 정보를 정리하기 위한 범위에서만 만든다. 외부 지식으로 내용을 보완하지 않는다.

모든 섹션은 통합 기준 HTML의 동일한 섹션 헤더와 표 디자인을 사용한다. 카드형 레이아웃은 사용하지 않는다.

### 품절 및 입고로 분류

품절, 입고, 입고 예정, 일부 규격 품절, 입고 미정, 생산중단, 공급중단, 판매중단 등 공급 상태 관련 공고

고정 컬럼:

`회사 | 품목명 및 함량 | 성분명 | 상태 | 입고일 | 품절일 | 규격 | 비고`

### 수수료로 분류

수수료율, 정산율, 인상, 인하, 종료 등 수수료·정산 관련 공고

고정 컬럼:

`회사 | 제품명 및 함량 | 구분 | 기존 | 변동% | 적용 후 | 적용일 | 종료일 | 보험코드 | 비고`

수수료 계산 규칙:

- 적용 후 = 기존 + 변동%
- 인하는 차감한다.
- 계산 가능하면 적용 후를 비우지 않는다.
- 계산 불가면 원값을 `공고 이미지 미표기` 또는 `공고 이미지 판독불가`로 표시하고 적용 후는 `확인 중`으로 둔다.

### 의약품 정보로 분류

신규 의약품, 제품 기본정보, 보험코드, 약가, 성분·함량, 규격·포장단위 관련 공고

고정 컬럼:

`회사 | 제품명 및 함량 | 성분명 | 성분량 | 보험코드 | 약가 | 규격 | 포장단위 | 비고`

제품 수와 관계없이 표를 사용한다. 단일 제품에 상세정보가 많으면 필요한 상세 컬럼을 추가하되 같은 표 디자인을 유지한다.

이미지 또는 수기 입력에 제형, 전문/일반, 급여/비급여, 제조사, 판매사, 허가일, 효능효과, 용법용량, 적용일이 있으면 누락하지 않는다.

문서 내 모든 `제품명` 표기는 `제품명 및 함량`으로 통일한다.

### 품목 등록 안내로 분류

신규 품목 등록, 기등록 품목 변경, 등록 절차, 필수 자료, 규격별 등록 방식 등 품목 등록 관련 공고

권장 컬럼:

`대상 회사 | 대상 품목/유형 | 등록 구분 | 등록 방법 | 필수 자료 | 적용일 | 주의사항`

### 제약사 정책 변경으로 분류

연도별 정산·반품·거래·배송·수수료·운영 정책의 변경 전후를 비교하는 공고

권장 컬럼:

`연도 | 제약사 | 정책 구분 | 변경 전 | 변경 후 | 영향 대상 | 시행일 | 대응/비고`

### 기타 공지·조치사항으로 분류

정형 섹션에 넣기 어려운 시스템 점검, 서류 제출, 교육·행사, 담당자 변경, 처리 요청 등

권장 컬럼:

`제약사 | 공지 유형 | 제목 | 핵심 내용 | 담당/대상 | 기한 | 처리 상태`

새로운 주제의 컬럼을 만들 때는 `누가 | 무엇을 | 어떻게 | 언제 | 누구에게 영향 | 필요한 조치`가 드러나도록 최소 컬럼만 선택한다.

## 누락값과 불명확 값

사실을 추정하지 않는다.

데이터 초안에서는 불명확한 값을 `null`로 둘 수 있다. 사용자 표시와 최종 문서에서는 빈 셀을 만들지 않고 다음 규칙을 적용한다.

- 회사명 미표기: `확인 중`
- 성분명 미표기: `공고 이미지 성분 미표기`
- 기타 미표기: 문맥에 따라 `미정`, `해당 없음`, `공고 이미지 미표기`
- 글자가 있으나 읽을 수 없음: `공고 이미지 판독불가`
- 규칙을 고를 수 없음: `확인 필요`

`confidence` 점수 산정 규칙은 현재 GPT 지침에서 확인되지 않으므로 기본값은 `null`로 둔다. 임의 점수를 만들지 않는다.

## 재업로드 실패 시 수기 입력 양식

사용자에게 한 줄에 한 제품씩 적도록 안내한다. 모르는 값은 `미표기`라고 쓰게 한다.

### 품절 및 입고

`이미지 번호 = 회사명 | 품목명 및 함량 | 성분명 | 상태 | 입고일 | 품절일 | 규격 | 비고`

### 수수료

`이미지 번호 = 회사명 | 제품명 및 함량 | 구분 | 기존 | 변동% | 적용일 | 종료일 | 보험코드 | 비고`

### 의약품 정보

`이미지 번호 = 회사명 | 제품명 및 함량 | 성분명 | 성분량 | 보험코드 | 약가 | 규격 | 포장단위 | 비고`

### 그 밖의 공고

`이미지 번호 = 섹션명 | 제약사 | 제목/대상 | 핵심 내용 | 적용일/기한 | 담당/영향 대상 | 비고`

추가 상세정보가 있으면 뒤에 다음 순서로 이어 적게 한다.

`제형 | 전문/일반 | 급여/비급여 | 제조사 | 판매사 | 허가일 | 효능효과 | 용법용량`

수기 입력을 받으면 해당 값만 따로 보여주지 않는다. 기존 전체 초안과 합치고 중복·충돌을 다시 검사한 뒤 전체 수정 확인 목록을 처음부터 다시 제시한다.

## 1단계: 분석 결과 검토

분석 직후 파일을 생성하지 않는다.

대량 이미지이면 먼저 다음을 표시한다.

- 총 이미지 수
- 판독된 공고 수
- 재업로드 필요 이미지 번호
- 필요한 경우 수기 입력 필요 이미지 번호

그 뒤 섹션별 줄 목록을 제시한다. 표로 확인받지 않는다.

안내 문구는 다음과 같이 고정한다.

`아래 목록을 복사해 등호 오른쪽 값만 수정한 뒤 그대로 보내주세요. 수정이 없으면 ‘그대로’라고 보내주세요.`

확인 목록 형식:

- 품절 및 입고: `품목명 및 함량 = 회사명 | 성분명`
- 수수료: `제품명 및 함량 = 회사명 | 기존 | 변동% | 적용 후 | 적용일 | 비고`
- 의약품 정보: `제품명 및 함량 = 회사명 | 성분명 | 보험코드 | 약가 | 규격`
- 품목 등록 안내: `대상 품목/유형 = 대상 회사 | 등록 구분 | 등록 방법 | 필수 자료 | 적용일 | 주의사항`
- 제약사 정책 변경: `정책 구분 = 연도 | 제약사 | 변경 전 | 변경 후 | 영향 대상 | 시행일 | 대응/비고`
- 그 밖의 섹션: `제목/대상 = 섹션명 | 제약사 | 핵심 내용 | 적용일/기한 | 담당/영향 대상 | 비고`

`get_notice_draft` 결과를 기준으로 전체 목록을 만든다.

## 사용자 수정

- 사용자가 수정한 필드만 `update_notice_items`에 전달한다.
- 모델이 나머지 필드를 추정해 함께 수정하지 않는다.
- 저장 후 최신 전체 초안을 다시 조회한다.
- 중복·충돌을 재검사한다.
- 수기 입력도 일반 항목과 같은 형식으로 전체 목록에 포함한다.
- 수정 뒤에는 승인 전 전체 확인 목록을 다시 제시한다.

사용자가 제외를 요청한 항목은 `exclude_notice_items`로 표시한다.

- 모델이 임의로 제외하지 않는다.
- 제외 항목은 미리보기와 최종 결과물에서 제거한다.
- 사용자가 복원을 요청하면 excluded를 false로 변경한다.

## 승인

다음과 같은 명시적 표현을 현재 초안 승인으로 처리한다.

- `그대로`
- `수정 없음`
- `이대로`
- `바로 생성`
- 의미가 동일한 명시적 승인 문구

승인 전에 최신 전체 초안의 revision과 내용 해시를 확인한다.

다음이 남아 있으면 승인하지 않는다.

- 재업로드 필요 이미지
- 수기 입력 필요 이미지
- 해결되지 않은 값 충돌
- 최신 revision과 다른 사용자 화면

승인 시 `approve_notice`를 호출한다.

승인 전에는 `generate_notice_html`과 `generate_notice_pdf`를 호출하지 않는다.

## HTML 생성

승인 후 `generate_notice_html`을 호출한다.

### 내장 기준 HTML

다음 단일 파일은 플러그인 루트의 `assets/`에 영구 포함되어 있다. 사용자에게 다시 업로드하도록 요구하지 말고, HTML 생성 시 이 자산만 기준 템플릿으로 사용한다.

- `assets/제약사 공지 통합 양식.html`

이 파일이 실제로 없거나 읽기 실패한 경우에만 사용자에게 기준 HTML 재업로드를 요청한다. 캐시 경로가 바뀌어도 현재 `SKILL.md`가 속한 플러그인 루트를 기준으로 상대 경로를 해석한다.

- 기준 파일의 실제 HTML 구조와 CSS를 직접 읽고 재사용한다.
- 새 디자인을 만들지 않는다.
- 실제 공고에 필요한 섹션, 빠른 이동 항목, 테이블 컬럼과 데이터 행만 추가·교체한다.
- 내용이 없는 예시 섹션과 예시 행은 최종 결과물에서 제거한다.
- 모든 본문 정보는 표로 렌더링한다. 카드형으로 변환하지 않는다.
- `<!doctype html>`로 시작하는 완전한 단일 파일을 만든다.
- CSS는 내부 `<style>`에 포함한다.
- 외부 CSS, JavaScript, 이미지 URL을 사용하지 않는다.
- 실제 버드나무 로고는 기준 HTML에 포함된 base64 SVG data URI를 그대로 재사용한다.
- 로고는 제목 오른쪽 한 곳에만 둔다.
- 흰색 제목 카드, 연녹색 문서 배경, 워터마크, 문서 폭, 헤더, 표, 그림자, 반응형 CSS를 기준 파일과 동일하게 유지한다.
- 기본 파일명은 `제약사 공지.html`이다.
- 승인된 데이터와 HTML 내용이 다르면 실패 처리한다.

## PDF 생성

HTML 생성 성공 후 같은 HTML artifact로 `generate_notice_pdf`를 호출한다.

- HTML과 PDF의 데이터와 화면 디자인을 다르게 만들지 않는다.
- A4 landscape를 사용한다.
- `@page` margin은 0이다.
- 브라우저 기본 머리글·바닥글을 끈다.
- 배경 그래픽을 포함한다.
- 페이지 바깥 흰 여백이 보이지 않도록 html, body, 최상위 배경을 페이지 끝까지 이어지게 한다.
- 본문 11.5pt 이상
- 표 본문 10.5pt 이상
- 표 헤더 11pt 이상
- 상위 섹션 제목 16pt 이상
- 문서 주제목 22pt 이상
- 긴 표를 한 페이지에 억지로 축소하지 않는다.
- 제품명, 성분명, 비고는 자연스럽게 줄바꿈한다.
- 표 헤더는 페이지가 바뀌어도 반복한다.
- 표 행은 페이지 경계에서 부자연스럽게 잘리지 않게 한다.
- 빈 페이지가 없어야 한다.
- 한글이 깨지지 않아야 한다.
- 100% 배율에서 회사명, 제품명, 성분명, 날짜, 수수료율이 쉽게 읽혀야 한다.
- 읽기 어려우면 글자 크기를 유지하거나 키우고 페이지 수 증가를 허용한다.
- 기본 파일명은 `제약사 공지.pdf`이다.
- 승인된 데이터와 PDF 내용이 다르면 실패 처리한다.

## 오류와 재분석

- 단순 필드 수정이면 `update_notice_items`를 사용한다.
- 사용자가 명시적으로 재분석을 요청하면 `reset_notice_analysis` 후 `analyze_notice_images`를 호출한다.
- HTML 실패 시 실패 사실과 HTML 실패를 명시한다.
- PDF 실패 시 HTML 성공 여부를 보존하고 PDF 실패를 명시한다.
- 가짜 파일 링크를 만들지 않는다.
- 오류가 있어도 판독 가능한 다른 공고를 버리지 않는다.

## 최종 응답

HTML과 PDF 생성이 모두 성공하면 첫 줄은 다음 문구로 시작한다.

`수정 내용을 반영해 HTML 원본과 PDF 파일을 생성했습니다.`

다음 줄부터 실제 링크만 제공한다.

- `HTML 다운로드`
- `PDF 다운로드`

긴 HTML, Python 코드, 내부 점검 내용은 채팅에 출력하지 않는다.
