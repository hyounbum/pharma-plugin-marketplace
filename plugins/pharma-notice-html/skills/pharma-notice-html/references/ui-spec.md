# ui-spec.md

## 1. 목적

ChatGPT 안에서 이미지 분석 초안을 제약사별·분류별로 검토하고, 사용자가 허용된 필드를 수정·제외한 뒤 승인할 수 있는 편집 UI를 정의한다.

이 UI는 새 업무 기능을 만들지 않는다. 다음 현재 기능만 화면화한다.

- 전체 초안 조회
- 필드 수정
- 항목 제외/복원
- 재분석
- HTML 미리보기
- 그대로 승인
- 승인 후 HTML/PDF 생성 및 다운로드
- 오류·재업로드 필요 상태 표시

## 2. 데이터 원칙

- UI의 유일한 데이터 원본은 `get_notice_draft`의 구조화 결과다.
- UI는 `noticeId`, `revision`, `approvalStatus`, `approvedContentHash`를 유지한다.
- 모든 저장 요청에 `expectedRevision`을 전달한다.
- 저장 성공 뒤 서버가 반환한 최신 notice로 전체 UI를 교체한다.
- UI 로컬값을 서버 초안보다 우선하지 않는다.
- `excluded: true` 항목은 편집 화면에서는 보이되 제외 상태로 표시하고, 미리보기/최종 결과에서는 보이지 않는다.
- 사용자에게 보이는 빈 필드는 `미표기` 또는 `확인 필요`로 표시할 수 있지만, 서버 전송 시 원래 `null`과 사용자가 입력한 실제 문자열을 구분한다.

## 3. 화면 구조

```text
┌──────────────────────────────────────────────────────────────┐
│ 제약사 공지                                                  │
│ 상태 · 총 이미지 수 · 공고 수 · revision · 재업로드 경고     │
├──────────────────────────────────────────────────────────────┤
│ [제약사 A] [제약사 B] [확인 중]                              │
├──────────────────────────────────────────────────────────────┤
│ 품절 및 입고                                                 │
│  └ 항목 카드/행                                              │
│ 수수료                                                       │
│  └ 항목 카드/행                                              │
│ 의약품 정보                                                  │
│  └ 항목 카드/행                                              │
├──────────────────────────────────────────────────────────────┤
│ [저장] [그대로 승인] [재분석] [HTML 미리보기] [PDF 생성]     │
└──────────────────────────────────────────────────────────────┘
```

### 3.1 상단 상태 영역

표시 항목:

- 작업 ID
- 상태
- 총 이미지 수
- 판독된 공고 수
- 재업로드 필요 이미지 번호
- 수기 입력 필요 이미지 번호
- 중복 이미지 번호
- 현재 revision
- 승인 상태

상태별 배지:

| 상태 | 표시 |
|---|---|
| 업로드 중 | `이미지 업로드 중` |
| 분석 중 | `이미지 분석` |
| 검토 가능 | `분석 결과 검토` |
| 수정됨 | `사용자 수정` |
| 승인됨 | `승인 완료` |
| 생성 중 | `HTML/PDF 생성` |
| 오류 | `오류 또는 재분석 필요` |

### 3.2 제약사별 탭 또는 영역

- 회사가 2곳 이상이면 탭을 사용한다.
- 회사가 1곳이면 단일 영역으로 표시할 수 있다.
- 회사명 미표기는 `확인 중` 탭으로 표시한다.
- 탭 순서는 원본 이미지에서 처음 등장한 순서를 유지한다.
- 회사명 수정은 현재 GPT의 수정 규칙에 포함되므로 회사 헤더에서 수정할 수 있다.
- 동일 회사명 병합 기준이 불명확하거나 충돌하면 자동 병합하지 않고 경고를 표시한다.

### 3.3 분류별 표시

각 회사 탭 안에서 다음 순서를 고정한다.

1. 품절 및 입고
2. 수수료
3. 의약품 정보

세부 category는 해당 상위 섹션 안에서 표시한다.

| category 예 | 상위 섹션 |
|---|---|
| 품절, 입고, 생산중단, 공급중단, 판매중단, 일부규격품절, 입고미정 | 품절 및 입고 |
| 수수료변동, 정산중단, 신규금지 | 수수료 |
| 신제품, 약가변동 | 의약품 정보 |
| 기타 | 판독된 문맥에 따른 상위 섹션. 불명확하면 `확인 필요` |

`기타`의 상위 섹션 매핑은 현재 데이터만으로 결정할 수 없으면 사용자 검토를 요구한다.

## 4. 항목 편집 행

각 항목은 다음 정보를 표시한다.

### 항상 표시

- 항목 ID의 사용자 비노출 내부값
- 원본 이미지 번호 `sourceImageIndex`
- 분류 `category`
- 상태 `status`
- `confidence`가 null이 아니면 점수
- `userEdited` 여부
- `excluded` 체크박스
- 판독 불가/미표기 경고

### 수정 가능한 필드

| 화면 라벨 | 데이터 필드 | 입력 형식 | 빈값 허용 |
|---|---|---|---|
| 제약사 | `companyName` | 한 줄 텍스트 | 예. null이면 `확인 중` |
| 제품명 및 함량 | `productName` | 한 줄 또는 짧은 여러 줄 | 예 |
| 성분명 | `ingredient` | 여러 줄 텍스트 | 예 |
| 성분량/함량 | `dosage` | 한 줄 텍스트 | 예 |
| 보험코드 | `insuranceCode` | 한 줄 텍스트 | 예 |
| 약가 | `price` | 한 줄 텍스트 | 예 |
| 기존 수수료율 | `previousRate` | 한 줄 텍스트 | 예 |
| 변동% | `changeRate` | 한 줄 텍스트 | 예 |
| 적용 후 | `newRate` | 한 줄 텍스트 | 예 |
| 상태 | `status` | 한 줄 텍스트 또는 현재 분류 선택 | 예 |
| 적용일 | `effectiveDate` | 원문 보존 텍스트 | 예 |
| 정산기간/종료일 | `settlementPeriod` | 원문 보존 텍스트 | 예 |
| 비고 | `remark` | 여러 줄 텍스트 | 예 |
| 항목 제외 | `excluded` | 체크박스 | 아니오, boolean |

### 수정 필드 규칙

- 날짜를 강제로 ISO 형식으로 바꾸지 않는다.
- 보험코드의 앞자리 0을 보존한다.
- 약가와 수수료율의 단위를 제거하지 않는다.
- 사용자가 수정하지 않은 필드는 patch에 포함하지 않는다.
- 사용자가 필드를 지웠으면 `null`로 보낼지 빈 문자열로 보낼지 UI에서 명확히 구분한다. 권장값은 `null`.
- 적용 후 수수료율을 서버가 계산할 수 있으면 서버 계산 결과를 다시 표시한다.
- 서버가 충돌을 반환하면 충돌 필드에 경고를 표시하고 승인 버튼을 비활성화한다.

## 5. 항목 제외

- 각 항목에 `결과물에서 제외` 체크박스를 둔다.
- 체크 변경은 로컬 변경 상태로 표시하고 `저장` 시 반영한다.
- 저장 시 일반 필드 수정과 제외 변경을 분리 호출한다.
  1. `update_notice_items`
  2. 최신 revision 수신
  3. `exclude_notice_items`
  4. `get_notice_draft`
- 제외된 항목은 흐리게 표시하고 `제외됨` 배지를 붙인다.
- 복원은 체크 해제 후 같은 도구를 `excluded: false`로 호출한다.
- 전체 항목을 제외하는 경우 처리 정책은 **[확인 필요]**이므로 출시 전에 결정한다.

## 6. 버튼과 MCP 도구 매핑

| 버튼/동작 | 활성 조건 | 호출 도구 | 호출 순서 | 성공 후 | 실패 시 |
|---|---|---|---|---|---|
| 저장 | `REVIEW_DRAFT` 또는 `USER_EDITING`, 로컬 변경 존재 | `update_notice_items`, 필요 시 `exclude_notice_items`, `get_notice_draft` | 수정 → 제외 → 조회 | 최신 전체 초안으로 화면 교체, 상태 `USER_EDITING` | 필드 오류 표시, version conflict면 최신 초안 재조회 후 사용자에게 재검토 요청 |
| 그대로 승인 | 로컬 미저장 변경 없음, 미해결 충돌/재업로드 없음 | `get_notice_draft`, `approve_notice` | 최신 조회 → hash 검증 → 승인 | 상태 `APPROVED`; 현재 GPT 규칙에 따라 HTML·PDF 생성 흐름 시작 | 승인 불가 사유를 상단에 표시 |
| 재분석 | 분석 결과가 있고 사용자가 명시적으로 선택 | `reset_notice_analysis`, `analyze_notice_images`, `get_notice_draft` | reset → analyze → 조회 | 새 전체 초안 표시, 승인 상태 PENDING | 기존 초안은 실패 이유와 함께 보존 가능한 방식으로 처리 **[저장 정책 확인 필요]** |
| HTML 미리보기 | 분석 완료 후 | `render_notice_preview` | 최신 revision으로 호출 | ChatGPT 내 미리보기 영역 열기 | 템플릿/렌더 오류 표시, 최종 파일 링크를 만들지 않음 |
| PDF 생성 | 승인 완료 | `generate_notice_html`이 없으면 먼저 호출, 그 뒤 `generate_notice_pdf` | HTML 확인/생성 → PDF | PDF 다운로드 표시. 현재 GPT 최종 흐름에서는 HTML 다운로드도 함께 표시 | 승인 전이면 버튼 비활성화, PDF 실패 시 HTML 성공 상태 유지 |
| 항목 제외 체크 | 검토/수정 상태 | 저장 전 로컬 변경 | 저장 버튼에서 도구 호출 | 제외 배지 표시 | 서버 실패 시 체크 상태를 서버값으로 복구 |
| 탭 이동 | 언제나 | 없음 | 없음 | 회사별 영역 전환 | 없음 |

## 7. 승인 버튼 세부 동작

`그대로 승인`을 누를 때:

1. 저장되지 않은 변경이 있으면 승인하지 않는다.
2. `get_notice_draft`로 최신 revision을 가져온다.
3. 재업로드 필요 이미지, 수기 입력 필요 이미지, 충돌이 없는지 확인한다.
4. 제외 항목을 포함한 정규화 초안의 hash를 사용한다.
5. `approve_notice`를 호출한다.
6. 승인 성공 후 `generate_notice_html`을 호출한다.
7. HTML 성공 후 `generate_notice_pdf`를 호출한다.
8. 두 artifact의 승인 content hash가 같은지 확인한다.
9. 실제 다운로드 UI를 표시한다.

현재 GPT 규칙상 HTML과 PDF 중 무엇을 만들지 다시 묻지 않는다.

## 8. HTML 미리보기

- `render_notice_preview`가 반환한 UI resource를 ChatGPT 안에 렌더한다.
- 미리보기는 현재 revision을 표시한다.
- 제외 항목은 렌더하지 않는다.
- 미리보기 자체가 승인 상태를 만들지 않는다.
- 미리보기 URI를 최종 파일 다운로드 링크로 사용하지 않는다.
- 미리보기 HTML도 외부 CSS/JS/이미지 URL 없이 기준 자산을 사용해야 한다.
- 기준 파일과 다른 독립 디자인을 만들지 않는다.

## 9. 오류 UI

### 이미지 오류

- `이미지 4: 재업로드 필요`
- `이미지 7: 수기 입력 필요`
- 판독 가능한 다른 항목은 계속 표시한다.

### 수정 충돌

- 충돌 필드 옆에 원본 판독값과 사용자 수정값을 구분해 표시한다.
- 서로 다른 이미지의 충돌값은 서버가 임의 선택하지 않는다.
- 사용자가 값을 확정하기 전 승인 버튼을 비활성화한다.

### 버전 충돌

- `VERSION_CONFLICT` 수신 시 자동 덮어쓰기하지 않는다.
- 최신 초안을 다시 조회한다.
- 사용자의 미저장 로컬 변경과 최신 서버값을 함께 표시하는 방식은 **[확인 필요]**다.

### 생성 오류

- HTML 실패: `HTML 생성 실패`와 오류 코드 표시, 가짜 링크 금지
- PDF 실패: HTML 다운로드는 유지하고 `PDF 생성 실패` 표시
- 한글 깨짐: `KOREAN_FONT_UNAVAILABLE` 또는 glyph 검사 실패 표시
- 페이지 넘침/가독성 실패: PDF artifact를 최종 성공으로 표시하지 않음

## 11. 한글·접근성

- UI 문서 인코딩은 UTF-8이다.
- 한글 입력 조합 중 저장 단축키가 실행되지 않게 한다.
- 표/카드 라벨은 `label`과 입력 요소를 연결한다.
- 색상만으로 상태를 구분하지 않고 텍스트 배지를 함께 표시한다.
- 정확한 접근성 목표 수준은 **[확인 필요]**다.
